# Android 原生完整移植对齐清单

内容核对日期：2026-10-24；文档体系整理日期：2026-10-25。比较基线：当前仓库旧 Android 客户端（React / Capacitor）与 `nativeApp`（Kotlin / Compose）。
初次盘点依据源码、Android 能力开关和已有首页截图，当时未重新操作应用。
本清单集中维护迁移覆盖、验收要求与关键验证结论；现有验证摘要见文末，本次文档整理未重跑应用或账号验收。

## 目标与判定方式

先完整迁移旧 Android 已开放的功能、交互、设置及状态反馈。保留 Rust 核心。
原生版目前具备基本播放和通用页面，但大量页面内操作、配置和呈现能力尚未对齐。
用户明确希望完整移植；“听歌用途”不作为省略旧功能的依据。

表中“已有代码”仅表示代码中存在实现；“部分”表示只覆盖一部分用户能力；“缺失”表示原生界面或调用未接入。
这三种状态都不代表真机验收完成。后续任务使用编号追踪，发现细项时继续拆分。

## 旧 Android 已关闭或未开放的能力

按当前 [Android 能力表](../../packages/yaqmc-client/src/bridge.ts)及布局 / 客户端门禁单列：

- 桌面歌词 / 歌词岛、桌面窗口 / 托盘 / 全局快捷键、插件、本地 HTTP API：旧 Android 未开放。
- 常规文件导出与统计 JSON / CSV 导出：客户端受 `fileExport = false` 限制；不能因为共享统计页有按钮就算作旧 Android 可用。
- 诊断包是例外：设置页显式允许 Android 导出 / 系统分享，因此 T03 属于真实迁移缺口。
- 背景图片导入受 `fileImport = true` 支持，属于 O03 的迁移范围。

这些平台边界用于准确比较；扩展旧 Android 没有的桌面能力需另定范围。

## 后续开发与完成条件

实施顺序已在[项目规划](project-plan.md)中确认：基础与整体界面、浏览与账号、播放器与队列、歌词与个性化、
统计与维护、交付与替换。组内同时处理已有可靠性问题；靠后实施仍属于完整移植范围。

N01 的返回行为是用户已确认差异：保留当前原生版逻辑，具体源码基线见项目规划。
本项决定本身不表示其他导航差异已对齐；第一批返回路径的真机检查结果见文末验证摘要。

每项迁移应核对：旧版可复现入口、原生等效操作与状态、设置保存、失败 / 取消反馈、自动检查及真机证据。
真实账号写入和升级 / 数据兼容验收单列，只有实际执行才标记通过。
全部适用项完成并验收，或由用户明确确认某项差异后，才可称为完整移植并讨论替换旧版。

已有两版首页截图显示布局、顶部入口和底部播放操作存在明显差异；账号、主题与内容不同，截图仅作布局观察。
初次盘点查看的是本地被忽略的 `artifacts/android-native-comparison/` 中的既有截图。
第一批新增的界面测试截图使用 `batch1-*` 文件名，验证范围与旧版对比基线分别记录。
本清单未用缺口条数计算“完成百分比”，也未将共享 Rust 能力重复计为待重写功能。
